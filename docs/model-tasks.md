# 个人文本模型任务

入口`/tasks`。当前范围是个人预算下的文本推理任务，包含可用模型目录、原输入上传、可信报价、用户确认、提交与输入绑定、只读恢复、任务状态/取消、费用与纯文本结果。它不提供完整Web Agent、多轮工具执行、云工作区或支付。

契约快照0.3.0固定服务端`bd896b70b598f45f22beae5ec2cc7977fec915da`，新增artifacts/pricing共四份文件。金额用严格字符串和BigInt；余额/预算预检查不能替代服务端事务冻结。报价不会消费积分，只有当前会话中新取得的原报价能产生内存中的确认对象；本地confirmed标记不能自行发起提交。

sessionStorage仅保存当前user/owner归属的原参数、对象描述符、报价及请求编号，不保存提示词、结果或凭证。恢复先按原Invocation只读查询；已有Job不重跑模型，404不等于旧请求已失败，不自动换键。原参数、对象和报价不可覆盖。批准尝试在首个await前记录，撤回标记阻止迟到的异步继续提交；清除后的记录不能被旧回调重新创建。

未提交输入可按原ID删除。已确认却尚未读到Job时，必须向服务端撤回原SubmitJob请求，只有当前用户/owner/Invocation/quote均匹配的prevented回执才能终结待核对状态。服务端未返回明确回执时仍保留原记录。已有Job继续使用真实取消/结算结果；回执不证明GPU释放，也不虚构退款。关闭标签页不自动取消已接受任务，任务事实以服务端列表为准。

模型结果必须是专用`application/vnd.orange.model-response+json`，并校验精确版本、长度（最多1MiB）、SHA、UTF8和严格结构。这里只接受无工具调用的文本，不执行HTML/脚本/工具。内容删除或权限拒绝清除展示内容，不把单一内容403当作登录失效并循环重登。执行与结算分别显示；succeeded/settled不意味着GPU回收已被认证。

`node scripts/check-model-tasks.mjs`运行客户端、构建和真实Chrome/API替身验证。实际链路由服务端`check-web-compute.py --web-repo <本仓库>`运行独立API/Worker/固定CPU模型/Counter/PG和Chrome，再用独立Counter核对真实计量、一次结算、CPU关闭及删除后的内容拒绝。该套测试的用户会话、价格和登记准入是显式夹具；普通真实OIDC仍由独立USER-OIDC验收覆盖。
